# 支付渠道管理系统原型

跨境支付渠道管理系统的交互原型：一条渠道从创建、录入四条产品线的能力，到合规、法务、报价、资金审核，再到上线，全部在一个系统里完成。

在线体验：https://silvius-eee.github.io/payment-channel-prototype/

这是作品集重建。渠道、人名、费率和所有数据都是虚构的。

## 要解决的问题

一条渠道要上线，常见三个问题：信息散在好几个地方；每一步该谁负责说不清；审批要靠人一遍遍去催。

## 四个核心设计

**多产品线录入。** Payin、Payout、发卡、全球账户四条产品线，各有自己的字段，比如收款币种、结算周期、卡组织、3DS 验证、资金托管。每条产品线显示还有几个字段待补充；只要还有缺口，就不能提交审批。

**按角色的数据隔离。** 同一个系统，不同的人看到的不一样：

| 角色 | 能看到 | 能改 | 能提交 |
| --- | --- | --- | --- |
| 商务 | 自己负责的渠道 | 自己负责的渠道 | 能 |
| 运营 | 自己负责的渠道 | 自己负责的渠道 | 能 |
| 产品 | 全部渠道 | 只能改支付方式 | 不能 |
| 负责人 | 全部渠道 | 不改字段，可以调整负责人 | 不能，负责报价和终审 |

**多级审批与退回。** 合规、法务、报价、资金、上线五道审批。任何一道都可以退回；补充后重新提交，会回到被退回的那一步继续，不用从头再走。上线后业务字段冻结，只有负责人能调整渠道负责人。每一次提交、修改、通过和退回都留有记录。

**FI Agent。** 侧边栏的问答助手，回答渠道支持什么能力、费率是多少、报价能赚多少。它遵守同样的数据隔离：你是商务时，它只回答你负责的渠道，问别人的渠道会被拒绝。

原项目中，FI Agent 接入了大模型 API 做原型验证。这个公开原型里是基于原型数据的规则问答，没有接入大模型，界面上也标明了。

## 推荐的体验路线

1. 默认身份是商务“周舟”。列表里五条渠道只看得到三条，另外两条显示为不可见。
2. 打开渠道 A：发卡和全球账户还有 3 个字段待补充，“提交审批”是灰的。把它们补齐，就能提交。
3. 用页面上的“演示”按钮模拟合规、法务团队通过；走到报价时，商务点不了，切换到“负责人”才能审批。
4. 让资金审核退回，再切回商务重新提交，看它从资金这一步继续。
5. 切换到“产品”，打开任意一条渠道：只有支付方式能改。
6. 在 FI Agent 里问“渠道 C 的费率是多少？”，商务会被拒绝，负责人能看到。

右上角“重置演示”可以随时恢复初始数据。

## 技术

纯前端，没有依赖，也不需要构建。直接打开 `index.html`，或者用任意静态服务器都能运行。

```text
index.html   页面骨架
style.css    样式
data.js      虚构的渠道、角色、产品线和审批节点
app.js       渲染、权限规则、审批流和 FI Agent
```
